# The appliance has its own Keycloak (2026-11-06, #290)

- The appliance runs its own Keycloak, `magnus-appliance-kc`, made and kept by `release/identity-on-appliance.sh CONFIG TUNNEL_ORIGIN`. Reason: sign-in and the admin console depend on Keycloak (owner, 2026-11-06: "a dependency that must exist for any operation"), and the one they used belonged to the retired `magnus-product` deployment, which was removed with its realm the same day. This repo is the only Magnus repository (owner, 2026-11-06), so what the appliance depends on is made here.
- Every setting comes from the appliance's `magnus.toml`: the public name and realm from `[sign_in.oidc] issuer`, the private admin origin from `status_admin_url` (loopback HTTPS, a CA of its own written to `status_admin_ca`), the database server from `[database] url` (entered as the administrator in `admin-url`, as `magnus migrate` does), the people from `[[people]]`, the console's names from `[admin]`. The one value the config does not hold, the loopback address the tunnel reaches, is an argument. The image is the digest `dev/keycloak.sh` pins. Reason: nothing is hardcoded (owner, 2026-11-06).
- Production mode, data in a `keycloak` database on the appliance's own Postgres, plain HTTP on loopback only for the tunnel, the admin API on loopback HTTPS only. Reason: the admin API stays off the public name (docs/remote-access-and-relay.md); the tunnel exposes only `/realms/<realm>/` and `/resources/`.
- Each person gets an account named by their `id` (the appliance matches `preferred_username`), with a first password Keycloak makes them change, kept owner-only beside the config. The status client's secret is made on each run and stored through the appliance's own `PUT /v1/secrets/{status_credential}`.
- `config/keycloak-client.py` no longer defaults to the retired deployment's files: `--admin-url`, `--admin-file` and `--ca` are required. It registers the appliance's client as DECISIONS.md (2026-10-30) records the live one: device-code grant, Direct access grants, Standard flow back to `http://127.0.0.1/*`, PKCE S256. Reason: those settings were made by hand on the old Keycloak and lost with it. Tests: `keycloak_client.rs` (both fail on the previous script).
- `identity.pyrallon.ai` moves to the appliance's tunnel `strix-alpha`, sign-in paths only; the retired `magnus-production` tunnel is deleted. Reason: the tunnel is how remote people reach the appliance securely (owner, 2026-11-06), and they sign in at that name.
